# Prompt audit of the repo skills

The record for issue #843: every skill in `skills/` audited with
`/doctor prompt-audit`, each finding fixed or kept with a reason, then
audited a second and a third time.

## Method

- **Tool.** In Claude Code 2.1.325, `/doctor prompt-audit <path>` hands off
  to the bundled `claude-api` skill's `prompt-audit` subcommand. That
  subcommand runs the guide `shared/prompt-audit.md`, with Step 0 scope,
  inventory, provenance, the pattern groups 1–4, the keep list, a report, and
  a proposed diff. This audit ran that subcommand once for each skill.
  `skill-creator` was large enough to split across three auditors.
- **Target model.** Claude Opus 5.5 (`claude-opus-5-5`), the model these
  skills run under. No audited file pins a different model.
- **Scope.** Each skill's `SKILL.md`, `references/` and `agents/`, plus any
  script containing prompt text or Anthropic API request code. The audit left
  out `evals/` (test fixtures), `docs/README.md` (human docs that never load
  into a session), `LICENSE.txt`, `CHANGELOG.md`, and `__pycache__`. The
  `.claude/skills/` symlinks point at an untracked `.agents/` directory and
  are not repo skills.
- **Prior partial pass.** PR #852 (issue #853) fixed three findings from an
  earlier audit of `skills/`: `budget_tokens` in `improve_description.py`, a
  "100-200 words" description cap, and `git stash push -u` in two skills. It
  recorded no per-skill results. This audit found none of the three still
  open.
- **Dispositions.** Each finding is either `fixed` in this change or `left`
  with its reason. Following the guide, low-confidence items are flagged and
  not edited. The same goes for edits that would change a standard several
  skills share, and for code changes that only a billed API run could
  verify.
